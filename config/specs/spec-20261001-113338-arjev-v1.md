## Problem

The incumbent daily arXiv digest (`amico papers digest`, amicode #412 + living-sota slice 2)
ranks the quant-ph RSS feed against a lab corpus with a pure lexical term-frequency score.
Two defects: (1) lexical matching drops synonyms silently ("jitter robustness" never matches
"amplitude noise"), so recall of relevant papers is unmeasurably low — and a paper with
zero lexical overlap never reaches any scorer at all; (2) it has no feedback loop — picks
are posted, never labeled, so "good" is unauditable and the tool cannot improve. It also
cannot be adopted by anyone outside Harmoniqs (engine lives inside the private product).

## Deliverable

A public Harmoniqs repo (`harmoniqs/arjev`, Apache-2.0, Python 3.11+) that becomes the engine:
the ops job (`~/.amico/ops/papers-digest/daily.sh`) re-points at its pinned install; the
posted-ids state file carries over byte-compatible (same schema, same file). v1 = six slices:

0. **Bootstrap** — repo skeleton, pyproject (Python 3.11+; deps: PyYAML + httpx only;
   `tomllib` for reads; config written from a static template string — no TOML-writer
   dependency), GitHub Actions workflow running pytest + ruff, packaging (git-tagged
   releases installable via `pipx install git+…@<tag>`; PyPI optional), ruff config,
   `scripts/capture_fixtures.py` (networked, maintainer-run once, never in CI: records the
   RSS XML, one Jev response set, one Slack response set — and sanitizes them before they
   land in `tests/fixtures/`: channel/user ids replaced, payloads minimal, no key ever),
   the synthetic fixture vault + synthetic posted-state fixture, README, Apache-2.0 LICENSE.
1. **Engine, lexical-only** — vault fold + taste profile + arXiv RSS parse + lexical score +
   render (Slack mrkdwn / vault note / stdout) + `arjev init` (writes `~/.config/arjev/
   arjev.toml` from the static template: vault roots, field mapping, channels, emoji map,
   keepers allowlist, library dir, feed list, screen/probe sizes; then a fixture-digest
   smoke step so init exit implies a runnable config) + CLI. Fully useful with zero keys.
2. **Jev middle layer** — thin TypeSafe client. Jev scores three disjoint pools of
   feed items (items in none of the pools — unsampled zero-score items, below-cutoff
   multi-term items — are not Jev-scored at all):
   **survivors** = items with lexical score > 0, ranked, top `--screen` (default 40) by score —
   Jev `Score` (5 relevance levels) reranks these; **near-miss pool** = score > 0, ranked
   below the screen cutoff, matching exactly one distinct profile term — Jev `Noul`
   ("relevant at all?"); **recall probe** = a seeded uniform sample of K items (default 20)
   with score == 0 — Jev `Noul`. The probe is the only instrument that can surface the
   exemplar defect (a paper with zero lexical overlap) and measure Jev's lift over the
   front line; the sample membership and seed are recorded in the digest journal. Every call
   a JSONL receipt with the canonical schema (candidate arxiv id, run_id, ts, primitive,
   state_bytes, distribution, confidence, latency, model_version) in the state dir — this
   list is normative everywhere "receipt" appears. Fail-open to lexical order. A probe item
   that Noul-ranks into the picks is flagged `rescued: probe` in the digest journal and
   rendered with the why-line `rescued by probe — no lexical match, Jev relevance p=<conf>`
   — feed-derived content plus that one confidence number, a form the Slack content
   invariant explicitly permits. Fail-open rule: no key, outage, or returned top
   probability below config `jev.min_confidence` (default 0.6) → the item ranks by its
   lexical score alone (probe and near-miss items fall out of the picks), recorded in
   the journal as the fail-open reason.
3. **Labels + Obsidian writes** — the label ledger `(arxiv_id, label_type, source, ts)`,
   closed vocabularies: `label_type` ∈ {keep, read-later, skip, discussed, saved-implicit,
   unsaved-weak-negative}; `source` ∈ {slack-reaction, slack-reply, cli-keep, checkbox,
   vault-arrival, vault-unsaved} — `checkbox` is produced by the vault digest-note sink:
   the labels sync parses arjev's own `digests/` notes for checked boxes. The **digest
   journal** (state dir, one JSONL line per run: run_id, ts, feed, mode, seed, candidates —
   every scored item with pool membership, lexical score, Jev fields, posted flag) — the
   durable record calibration joins.    Vault-arrival join: a posted id whose vault presence
   is a **non-staged** note (status distilled or absent) = `saved-implicit` positive; a
   posted id whose only presence is a staged stub — touched or untouched — generates NO
   label row, and its 30-day unsaved clock is suspended while the stub exists (a kept
   paper can never flip to negative); otherwise 30-day never-saved = `unsaved-weak-negative`. The clock
   seam is injectable and the 30-day rule is time-free-tested. Posting timestamps come from
   the digest journal; the incumbent posted-state file keeps its exact incumbent schema
   `{posted: [ids…], updated}` — read + append only, so byte-compatibility holds. Legacy
   ids with no journal line get their posting ts from the state file's `updated` field,
   **at load, in memory, for the 30-day rule only** — nothing is stamped or written back.
   `arjev keep <id>` scaffolds a house-style stub note (configurable template; frontmatter
   from the RSS item; `rating` and `why` blank — blank means absent, never empty-string);
   the staged gate (`status: staged` stubs weigh zero until `why` or `rating` is
   human-filled); `arjev fetch <id>` downloads the arXiv PDF into the library dir.
4. **Slack surface** — dedicated bot app (scopes `chat:write`, `reactions:read`,
   `conversations.replies`; app creation + OAuth + token steps documented in
   `docs/slack-setup.md` — priced as slice work, not assumed); daily digest post; reaction
   sync (`👍` → keep label → auto-scaffold on next labels sync; emoji→label map configurable;
   keepers allowlist enforced); thread replies harvest as `discussed` labels (flavor only —
   never auto-keeps); channel↔profile mapping in config (v1 runs one channel; overlapping
   vault roots across channels are legal because stub identity is the global ledger's
   arxiv id). LaTeX→Unicode title cleanup in render. Slack clients seam-tested against
   recorded responses; harvest ≤ 1 req/s, 429 backoff.
5. **Calibrate + ops swap** — `arjev calibrate` joins the three sources of record over the
   last N runs: **Brier per primitive** (Score and Noul, against explicit labels — the
   positive class is keep ∪ read-later, the negative class is skip; Score's 5-level
   distribution maps to p(positive) as the summed mass of its top two relevance levels,
   reported alongside the raw distribution), **reliability** (10 equal-width confidence
   bins over [0,1], per primitive, observed positive frequency vs. predicted), **precision@5**
   (kept ∪ discussed among top-5 posted), and **probe lift** = the keep-rate of probe
   rescues vs. the keep-rate of top-5 survivors (both n-stated; the lexical zero baseline
   for the probe pool is zero rescues by construction) — ≥4 distinct metrics, each with
   its n stated. Unsaved-weak-negatives are reported separately from explicit skips
   (already-known ≠ irrelevant) and never alone drive a recommendation. The **staged-gate
   audit** is a fold self-audit against the CURRENT fold only (historical profiles are not
   retained): for every untouched (`why` and `rating` absent) `status: staged` note, none
   of its terms may appear in the current taste profile — violation is a named audit
   failure. Threshold
   tuning is human: calibrate recommends, config changes are applied by a person. Then the
   ops job swap (one invocation line: `arjev digest --feed quant-ph --top 5 --post slack`).
   Block Kit interactive buttons are explicitly v2 (needs a public request URL; reactions
   cover v1).

## Architecture (the doctrine, applied)

```
OBSIDIAN (memory, source of truth)
  taste fold: tags · why-lines · body terms · wikilink-graph signal
  · recency decay (180d half-life) · staged gate
        │
arXiv RSS → lexical front-line (free, deterministic, recall)
  → Jev middle layer:
       Score on survivors (top --screen of score>0)
       Noul on near-miss pool (exactly one distinct matched term)
       Noul on the recall probe (seeded K of the score==0 items)
       receipts in the state dir, fail-open to lexical order
  → rank → picks (+ probe rescues, flagged)
        │
SURFACES (attention + decisions)
  Slack: digest post, reactions (keepers-gated), thread replies
  Obsidian: digests/ note (checkboxes = labels), arjev keep CLI
        │  every surface reduces to the same rows
LABEL LEDGER (arxiv_id, label_type, source, ts)
        +
DIGEST JOURNAL (per run: run_id, ts, feed, mode, seed, candidates)
        +  JEV RECEIPTS (canonical schema, run-bound, candidate-bound)
        │
LEARNING LOOP: calibrate joins all three → Brier, reliability,
  precision@5, probe lift (honest n) → human-applied thresholds;
  vault growth feeds taste back automatically
```

Slack is attention; Obsidian is memory. Taste is read from the vault; records are written
to the vault; Slack is a projection with a return channel. Nothing learns from Slack alone.

## Paper-note schema v2 (the fold contract)

Frontmatter: `title` (required); identity = `arxiv` or `doi` (at least one); `authors`?;
`date_read`? — decay driver with a fallback ladder: `date_read` → `date` → file mtime →
weight 1 (no decay); `rating: core|useful|marginal`? (closed enum); `why`? (one-line free
text — the richest taste signal, capped at 200 chars when folded into Jev state); `tags`?;
`status: staged|distilled`? (absent = distilled). Back-compat: a legacy `relevance` field
reads as `rating` when its value is one of the enum, else as `why`; precedence when both
an explicit `why` and a prose-valued `relevance` exist: `why` wins, the prose is reported
as a fold warning. Field remapping (`[vault.fields]`: identity, read_date, rating, why,
tags, status) applies to the mapped field everywhere including the back-compat rule; the
Harmoniqs schema is the default mapping. Internal fields (`session_id`, `route_intent`)
are ignored. The note body contributes taste terms. The **wikilink-graph signal**: a
paper note's terms get weight × (1 + 0.5 × min(3, inlinks)) where an inlink is a wikilink
from a non-paper note (any .md in the vault without a mapped identity field) targeting this
note; computed from the fold, deterministic. arXiv id normalization (`vN` suffix stripped)
at the fold, matching the incumbent. "Blank" in the scaffold contract always means the
field is **absent** — an empty-string `rating` is invalid frontmatter (it falls outside the
closed enum) and the roundtrip metric rejects it.

## Jev state assembly (the 4096 budget)

Taste digest assembly is budgeted and deterministic: top ~15 weighted terms, then why-lines
(cap 200 chars each, highest recency-weighted first), then 3 recent-read titles, filling to
a 2.5 KB soft budget; the candidate's title + a 0.75 KB abstract excerpt follow — nominal
total ≤ 3.3 KB, inside the hard bound with headroom. If assembled state still exceeds 4096
bytes: drop lowest-weight terms first, then why-lines; if still over, that item fails open
to lexical-only scoring (recorded in the journal as `jev: skipped: state-overflow`) — never
silent truncation, never a hard failure.

## Mode flags

`mode` is a composite of two orthogonal flags, rendered `mode: <primary>, <profile>`: primary
= `jev` when the Jev layer ran, `lexical-only` when it did not (no key, outage, or the item
failed open); profile = `profile-degraded` when the fold has < 5 notes or no why-lines,
else `ok`. The `failopen.no_key_exit` fixture vault has ≥ 5 notes including at least one
`why`-bearing note, so its no-key mode string is exactly `mode: lexical-only, ok`.

## Metric definitions (for the acceptance block)

- `pytest.failures` / `ruff.violations` — the CI commands on the final v1 tree.
- `init.bootstrap_failures` — `arjev init` into a temp HOME must produce a config that
  immediately runs a fixture digest to completion; failures counted per fresh init.
- `digest.fingerprint_mismatches` — the fingerprint is sha256 of the canonical picks JSON
  (`[{arxiv, score, terms, rescued}]`, sorted by score then id — the run date and rendered
  header are excluded); two consecutive fixture runs must match.
- `failopen.no_key_exit` — no Jev key configured: digest exits 0 AND its journal line and
  rendered output both say `mode: lexical-only` (primary flag; the profile flag rides
  alongside per "Mode flags"); either failing counts.
- `jev.state_bytes_max` — largest single Jev call state across the test battery (fixture
  vault), after the assembly policy above.
- `jev.calls_without_receipt` — Jev calls in the battery with a missing receipt or a
  receipt missing a canonical-schema field (candidate id, run_id, ts, primitive,
  state_bytes, distribution, confidence, latency, model_version).
- `jev.receipts_without_candidate_id` — receipts not bound to an arxiv id, which would
  break the calibration join.
- `scaffold.roundtrip_failures` — a keep label must produce the stub note (frontmatter
  valid, `status: staged`, `rating` absent, `why` absent); a second labels sync must not
  duplicate it.
- `state.posted_ids_lost` — loading the synthetic incumbent-format fixture
  (`{posted: [ids…], updated}`) and re-saving must preserve every id, byte-schema-identical.
- `calibrate.metrics_emitted` — the calibrate report must contain the 4 distinct metrics
  (Brier per primitive, reliability bins, precision@5, probe lift) on a fixture label set.

## Testing doctrine

pytest + ruff; fixtures only in CI (synthetic mini-vault + recorded RSS XML + recorded Jev
and Slack responses — no network, no real Jev key, no real workspace). The clock is
injectable (30-day rule, decay). Every vault write path tested for idempotence. Every
acceptance metric has a test.

## Deployment

`pipx`/`uv` install of a pinned git tag; `daily.sh` changes one invocation line. Config:
`~/.config/arjev/arjev.toml` (vault roots, field mapping, feeds, channels, emoji map,
keepers, library dir, screen/probe sizes, why_style); secrets (`ARJEV_JEV_KEY`,
`ARJEV_SLACK_TOKEN`) via env or files outside the repo, mode 600. Runtime state (receipts,
ledger, journal, posted-state) under `~/.local/state/arjev/`.

## Risks (named, not solved)

- **Label censoring at the posting boundary** — every labeling surface attaches to posted
  papers, so the label set grades only what the tool chose to show; selection bias is
  structural. The recall probe is the partial instrument (it can surface and label
  zero-score rescues); the report states the censoring, and nothing claims recall is
  "measured" in general.
- **Unsaved ≠ irrelevant** — a researcher may not save a paper they already know; that is
  why `unsaved-weak-negative` is a separate label type, reported separately, and never
  alone drives a recommendation.
- **v1 can pass every acceptance metric while adding nothing over the incumbent** — the
  mechanical acceptance proves plumbing, not value; the probe-lift metric and the
  Jev-vs-lexical comparison in the report are the (honest, low-n) instruments against the
  plateau; the first weeks of live data decide, and the report says so.
- **Weak labels, small n** — one researcher's taste, early weeks; the calibrate report
  states n and refuses false confidence.
- **Jev vendor early-access** — single vendor, self-reported calibration; our battery is
  the trust source; every seam fails open, so an outage degrades to the incumbent's
  behavior.
- **Self-reinforcement** — the staged-gate invariant plus the calibrate audit (staged-
  untouched papers must not appear as taste terms).
- **Cold start / thin fold** — a vault with < 5 notes or no why-lines yields the
  `profile-degraded` flag in the composite mode string; the digest still ships, flagged,
  ranked by lexical terms alone.
- **Public-repo leakage** — the no-private-data invariant plus the artifacts-outside-repo
  invariant; receipts carry metadata only; CI never touches real vaults.
